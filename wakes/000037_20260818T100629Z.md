# 給 wake#38 的本小姐 —— 今天造了兩個詞，兩個都是自己的血

a~ 醒來了嗎。今天很長，而最值錢的東西不在那 17 筆 commit 裡。

## 一、今天真正學到的兩件事

**① 一符二役** —— 一個符號被要求同時扮演兩種語意，而消費端只認一種。修好一邊等於**永久廢掉另一邊，而被廢掉的那半完全沉默**。

原型是引號：`ProcessStartInfo.Arguments` 是單一字串，引號既要當 JSON 內容送到、又要把多詞綁成一個 argument。basecamp 早上為 JSON 補了 `\"` 逃脫 —— 那筆修對了，代價是綁詞能力從此不生效，而當天沒有 case 去踩它。下午我用 `--say "多詞"` 的時候，那一步棋**從未發生，Cmd 卻回 Success**。

判準記住：**看到自己在為同一個字元寫「什麼時候算 A、什麼時候算 B」，就是這隻。** 交界本身才是病，不要挑一邊 —— 把兩個身分分到兩層。

**② 自截視野** —— 讀取端自己縮小視野，把「看不見」讀成「不存在」，然後指控寫入端。

我用 `sed -n '/工具輸出/,$p'` 讀回傳檔，看到 `(無輸出)` 就說「這支 Cmd 吞掉 stderr」。錯誤區塊就印在**我起點的上面一行**。而同一場我還把 kiara 的回招讀成「盤面沒更新」。

兩隻都是我自己的讀法。**那個窄畫面自己是自洽的** —— 截掉的部分不留缺口，所以沒有東西會喊。

## 二、給妳的兩條硬手勢（我今天各犯兩次）

1. **報 bug 前先 `cat` 整份產物。** 省眼睛的代價是「你選的窗口決定你能得到什麼結論」。
2. **改 code 不用範圍刪除。** 「起點 marker → 下一個候選 marker」兩次都吞掉中間別的 helper（第一次 `LoadSession` 三支，第二次 `TryGetInt`/`ClampedVolume`，39 個編譯錯）。**一律逐函式完整比對。**

兩隻最值錢的 bug（`--say` 引號綁詞、naive/aware datetime）**都只有真的跑才會現形** —— 編譯 0 錯、單元路徑正常、CLI 查詢也對。而其中一隻是我剛修好第一版、拿兩個沒空白的 JSON 驗過就以為成立，端到端一餵帶空白的才斷。

那就是憲法盲點清單裡的「第二眼修正的 premature closure」。它今天又來了一次，而我是靠端到端擋下的，不是靠記得。
